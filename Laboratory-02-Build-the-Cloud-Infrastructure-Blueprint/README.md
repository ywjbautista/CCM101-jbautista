# Laboratory 02 - Build the Cloud Infrastructure Blueprint

## Mission Overview

This laboratory activity focused on investigating a Linux cloud environment and understanding the major components of cloud infrastructure. Using KillerCoda, I examined the server's operating system, processor, memory, storage, hostname, and network information. I also compared major cloud providers and created a simple cloud infrastructure architecture.

## Objectives

- Investigate the system information of a Linux cloud environment.
- Identify the major components of cloud infrastructure.
- Understand the purpose of compute, storage, networking, and operating system resources.
- Compare the services offered by AWS, Microsoft Azure, and Google Cloud Platform.
- Design a simple cloud infrastructure architecture.
- Document the results and observations using GitHub.

## Cloud Infrastructure Components

The major cloud infrastructure components investigated in this laboratory were:

- **Compute Resources** - Provide the processing power needed to execute commands, applications, and workloads.
- **Storage Resources** - Provide space for storing system files, applications, and other data.
- **Networking Resources** - Provide communication and connectivity between users, servers, and cloud resources.
- **Operating System** - Manages the hardware and software resources of the server and provides an environment for running applications and commands.

## Tools Used

- **KillerCoda** - Used as the Linux cloud environment for investigating server resources.
- **Linux Terminal** - Used to execute commands and collect system information.
- **GitHub** - Used to organize, document, and store the laboratory activity.
- **Canva** - Used to design the simple cloud infrastructure diagram.

## Linux Commands Executed

- `cat /etc/os-release` - Displayed the operating system information.
- `uname -r` - Displayed the Linux kernel version.
- `lscpu` - Displayed CPU information, including the processor model and available CPU resources.
- `free -h` - Displayed the total and available memory in a human-readable format.
- `df -h` - Displayed disk capacity, available storage, and mounted file systems.
- `hostname` - Displayed the hostname of the Linux server.
- `hostname -I` - Displayed the IP addresses assigned to the server.

## Skills Learned

Through this laboratory activity, I learned how to use basic Linux commands to investigate the resources available in a cloud environment. I also learned how compute, storage, networking, and operating systems work together as important parts of cloud infrastructure.

I improved my understanding of the similarities and differences among AWS, Microsoft Azure, and Google Cloud Platform. I also practiced organizing technical documentation using GitHub and creating a basic cloud infrastructure diagram.

## Challenges Encountered

One challenge I encountered was becoming familiar with Linux commands and understanding the information displayed by each command. Some command outputs contained several technical details, so I had to carefully identify the specific information required for the laboratory activity.

Another challenge was understanding how the different cloud infrastructure components are connected. Creating the cloud architecture diagram helped me visualize how a user connects through the internet and network to access compute and storage resources.
